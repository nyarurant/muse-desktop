# Muse App 0.5.1

Muse と会話するための、非公式の Windows デスクトップアプリです。
会話画面はアプリ内の HTML/CSS/JavaScript で描画し、muse.ai の Web 版と同じゲートウェイ API を使って、Muse の VM と Noise XX で暗号化した通信を直接行います。

## 使い方

`dist/Muse App 0.5.1.exe` を起動します。Node.js のインストールは不要です。
ログインは必須です。ログインしていないと、アプリの画面全体がログイン画面になり、その中に表示される Meta のページで Muse アカウントにログインします（入力した内容はアプリには渡りません）。完了すると自動で接続し、いつもの画面に戻ります。
接続のたびに新しいトークンを取り直すので、ログインしたままなら接続が切れても自動で戻ります。ログインが切れたときは、またログイン画面になります。
接続情報は Windows の暗号化ストレージで暗号化し、`%APPDATA%/Muse App/muse-session.enc` に保存します。DevTools の通信記録（`.devtools` / `.har`）からの接続はできません（開発用の `npm.cmd run test:live` だけが使います）。
Meta の公式アプリではありません（Muse Desktop Community のコミュニティ版です）。

## 機能

- メインチャットとサイドチャットでの会話（Markdown 表示、ストリーミング表示、停止）
- サイドチャットのピン留め・名前変更・アーカイブ・削除、アーカイブ済みの表示
- 全チャットのメッセージ検索と、該当メッセージへのジャンプ
- 返信、リアクション、メッセージの削除、回答の出典リンク表示
- 画像・ファイルの添付（＋ボタン、貼り付け、ドラッグ＆ドロップ。1 つ 10 MB まで）
- フィード・アイデア・目標・ライブラリ（Muse が作ったファイルや画像の保存）
- 右パネル：アクティビティ、承認、近日開催予定
- Muse の承認の自動化（手動 / 自動 / 重要なものだけ確認 / Bypass）
- 作業が途中で止まったときの自動再開（`[System]` 付きの指示を送る。自分で停止したときは送らない）
- ローカル作業ページ（作業フォルダー・コマンド実行・実行ログ。メインウィンドウ内、`Ctrl+Shift+T` または入力欄横のボタン）
- 「PC 接続の設定」で SDK トークンの準備、メール／電話番号の認証、必要なアカウント選択や追加認証をアプリ内で完了。発行済みのトークンは再利用
- 認証済みの PC は起動時に自動で接続（切れたら自動で再接続。「このPC」をオフにするとその間は止まります）。「このPC」がオンの会話から、直接接続した PC へコマンド実行・ファイル操作を依頼。要求と結果は端末用の通信経路で送受信し、チャット本文のツール指示は解析しません
- ローカル作業ページの「PC タスク」から、新しいサイドチャットで PC 作業を開始することも可能

`Enter` で送信、`Shift+Enter` で改行します。
`Ctrl+N` で新しいサイドチャット、`Ctrl+K` で検索、`Alt+Shift+Space` でウィンドウの表示・非表示を切り替えます。
ウィンドウを閉じてもトレイに残り、Muse の承認の自動化や自動再開はそのまま動きます。

## 安全のために

PC 端末の認証情報は `%APPDATA%/Muse App/muse-device.enc` に暗号化して保存します。認証コードは保存せず、認証情報や SDK トークンの値は会話画面へ渡しません。PC 接続はアプリの起動後に自分でオンにします。端末の認証と、実際に端末へ操作が届くことは別に確認する必要があります。

端末通信は [Muse Gadget SDK](https://github.com/facebookincubator/muse-gadget-sdk/tree/main/linux) の `link.register` / `link.invoke` / `link.result` に対応します。PC 単体での認証スキーマは [Muse Desktop Bridge のプロトコル資料](https://github.com/chaitanyarahalkar/muse-desktop-bridge/blob/main/docs/protocol.md) を参照しています。非公式の連携であり、サーバー側の変更によって再認証が必要になる場合があります。

Muse の VM の暗号キーは VM が再起動するたびに変わります。Web 版と同じく新しいキーを受け入れて接続し、そのたびに画面で知らせて、変わった日時を `%APPDATA%/Muse App/gateway-pins.json` に記録します。
接続が切れたときは、アプリが自動で再接続します（3 秒から最長 1 分間隔。ログインが必要なときは止まって知らせます）。
承認の自動化を Bypass にすると、支払い・購入やメディアの送信も確認なしで許可されます。
ローカルのコマンド実行とローカルエージェントには、確認も作業フォルダーの制限もありません（コマンドは作業フォルダーで始まり、ファイルのパスは絶対パスか作業フォルダーからの相対パス）。サンドボックスではありません。
PC操作は「このPC」をオンにして依頼を送ったとき、またはローカル作業ウィンドウで開始したときに動きます。スマホ・Bluetooth・SDKトークンは不要です。アプリが既存の暗号化チャット通信で操作を受け取り、結果を返信します。Meta公式のペアリング済みデバイスとして登録する機能ではありません。
エージェントが読んだファイルの中身やコマンドの結果は Muse（Meta のサーバー）に送られます。通信や作業が中断した場合、ローカル操作の自動再実行は行いません。
返答は作業中の会話を直接購読して待ち、完了通知のあとに完成した本文を確認します。途中の文章を実行しません。履歴の定期取得は通知を取りこぼしたときの復旧用です。

## 開発

```powershell
npm.cmd install
npm.cmd run check
npm.cmd test
npm.cmd start
npm.cmd run dist:portable
npm.cmd run dist:win
```

実際のアカウントで接続を確認する（読み取りのみ）:

```powershell
npm.cmd run test:live -- --har="C:/path/to/capture.devtools"
```

`--send-test` を付けると、メインチャットとは別のサイドチャットを作り、無害な確認メッセージを 1 通だけ送って返信を確かめます。

アプリを `--remote-debugging-port=9337` 付きで起動しておくと、`npm.cmd run test:ui` で画面の動作（接続、履歴、送信、設定、検索、狭い画面）を確認できます。
この確認では実際に 1 通メッセージを送ります。

ファイル構成: `main.js` が Electron のメインプロセス、`desktop-api.js` が画面との IPC、`muse-client.js` が API クライアント、`noise.js` が暗号化通信、`app.html` / `app.css` / `app-renderer.js` が会話画面です。
承認の自動判定は `muse-approval-policy.js`、自動再開の判定は `auto-resume.js` にあります。PC の認証は `pc-auth.js`、端末通信は `native-device.js`、ローカルの実行は `native-executor.js`、ログイン検出は `login-flow.js` です。

Meta とは関係のないコミュニティ製のプロトタイプです。
